# 取料与定位

本文件解决审查中最费时的三件事：**该收哪些文件、怎么从稿件里抽出可定位的引文、多轮之间怎么追踪**。

---

## 一、收料清单（按优先级）

### 必需

1. **稿件正文**：优先取 `.md` / `.tex`（便于逐句定位）；`.docx` 需先转文本（转完必须核对节标题与表号，转换常丢表号）；PDF 只作备用，**定位容易错，慎用**。
2. **表格与图注**：单独列出的表文件优于正文内嵌表。图需能读到图注文字（图本身只在 L5 的"30 秒读懂"判断时需要）。
3. **目标期刊 + 文章类型**：一句话即可，但必须有。

### 强烈建议

4. **实验台账**：`claims.csv` / 消融结果 json / 统计输出（p 值、CI、多 seed 分布）/ 复算脚本。
5. **补充材料**：负向对照常藏在这里。
6. **上一轮报告**（非首轮）。

### 收不到时的替代方案

| 缺什么 | 如何替代 | 报告里怎么标 |
|---|---|---|
| 无台账 | 用稿件内部的表与正文互校（正文数字 vs 表数字），至少能抓口径不一致 | 输入完整度 = G1；所有溯源结论写"稿件内部互校，未对台账验证" |
| 只有摘要 + 图 | 只能审 L1（部分）、L4（部分） | 输入完整度 = G2；只出"部分审查"，**不给路径判定**，或给"暂无法判定" |
| 无 SI | 在报告边界声明里写明"补充材料未审，负向对照可能缺失" | 不得因"没看到负向结果"就判 F5，写"未找到（SI 未提供）" |

**"未找到"与"没有"必须区分。** 这是审查者最容易越界的地方：没找到负向结果不等于作者删了，判 F5 需要证据（比如上轮报告里有、这轮没了，或图表编号跳号）。

## 二、建立定位索引

动手前对稿件做一次编号映射：

```
§1 引言
  §1.3 末段（贡献列表）
§2 相关工作
§3 方法
  §3.2 模块 A
§4 实验
  §4.1 设置（数据集/指标/种子）
  §4.2 主对比  → Tab.2
  §4.3 消融    → Tab.3
  §4.4 鲁棒    → Fig.4
§5 讨论 / §6 结论
图：Fig.1 机制, Fig.2 ..., Supp.Fig.S1
表：Tab.1 设置, Tab.2 主结果, Tab.3 消融, Tab.4 ...
```

**索引写成文档或报告附录**，后面每张卡片都引用它。这样同一份报告在下一轮仍可精确定位（尤其是稿件改动后节号漂移时，用"表号 + 图注关键词"双定位）。

---

## 三、抽引文的规则

漏洞卡片的 `定位` 字段要求"章节 + ≤30 字引文"。抽引文的四条规则：

1. **优先抽"声称句"而不是"描述句"**。`We propose a novel ... outperforming ...` 比 `The architecture consists of ...` 更值得引。
2. **原文照抄，不改字**。需要省略用 `…`，不要顺手润色——引文一旦被改，作者会争论"我没这么写"。
3. **一句一卡**。同一段里两个独立问题 → 两张卡，不要合并（合并后复审判据会互相牵扯）。
4. **完整上下文至少读前后各 3 行**。很多"过度声称"其实下一句就给了限定，抽引文不读上下文会造出假漏洞——**这是本 skill 最需要防的误判。**

### 声称句的检索式（在稿件里搜这些词）

```
因果类：attribute to / due to / because of / results from / driven by / stems from
强度类：significantly / substantially / dramatically / remarkably / notably
最优类：state-of-the-art / SOTA / best / outperforms all / superior to
全称类：general / universal / all scenarios / any / across domains / robust in all
创新类：novel / first / pioneering / fundamentally / paradigm
```

把命中的句子逐条记下来（位置 + 原句），这就是第五节"声称轨"的输入。**通常一篇稿子会命中 15–40 句，逐条核对强度是审查最扎实的部分。**

---

## 四、数字核验的执行细节

抽样固定为四组（不要凭感觉抽）：

1. **摘要全部数字**（摘要数字是全稿被引最多、也最容易和正文脱节的）
2. **主表每列首行与末行**
3. **消融表里差值最大的两行**（最容易被过度解读的地方）
4. **任意一条负向/退化结果**（看作者怎么描述不利数据）

核验三问，每个数字都问：

- 这个值的**口径**是什么？（数据集 / 划分 / 随机种子数 / 评价协议 / 输入尺寸）
- 台账里有没有**同口径**的值？
- 如果口径不同，稿件有没有**注明**？

结论填四选一：`一致` / `一致（需注明口径）` / `不一致` / `未找到来源`。

**"一致（需注明口径）"是最常见的真实情况**——数字对，但稿子没写是哪个划分的结果。这本身是 P2（7.6/7.7 类），不要无视。

## 五、多轮追踪

### 差分追踪表（放在报告第十节）

| 上轮编号 | 状态 | 本稿证据 |
|---|---|---|
| V-01 | 已修复 | §4.2 新增 Tab.4 等容量对照 |
| V-02 | 部分修复 | 摘要已删 significantly，但 §4.2 正文仍写 significant，缺检验 |

状态四选一：`已修复` / `部分修复` / `未修复` / `申诉成立`。

**"部分修复"必须写明还缺什么**，否则下一轮无法判断这一条该不该继续挂着。

### 编号稳定性

- 新问题从 `V-<上一轮最大编号+1>` 起编。
- 旧问题编号**永不复用**。若问题性质变了（比如原问题解决了但引出新问题），新编一个号，并在差分表里注明"V-03 由 V-01 演化"。
- 若某轮整篇重写导致节号全变，用"内容锚点"代替节号定位（如"摘要结论句所引的 Tab.2 第 3 行"）。

### 判定漂移的检查

每轮结束问一句：**这一轮的路径判定与上一轮不同吗？** 若不同，必须在报告里解释"因为哪条证据变化导致判定变化"。判定无故漂移（尤其向有利方向漂移）是审查者被作者说服、而非被证据说服的信号——这时要回看上一轮的卡片，确认新证据是否真的存在。

## 六、稿件形态的特殊处理

| 形态 | 注意事项 |
|---|---|
| `.docx` | 转换后必查：表号、图号、公式编号、上标/下标（`R²`、`mAP@0.5` 易丢）、参考文献编号 |
| `.tex` | 直接读源码，图注在 `\caption{}`，表在 `table` 环境；注意 `\input` 拆分的子文件 |
| PDF | 只在无源文件时用；定位一律用"表号 + 图注关键词"，不用页码（页码会漂） |
| 双栏排版稿 | 图注与正文可能错位，抽引文时以语义判断归属，不按行位置 |
| 中英混排稿 | 同一概念中英混用是 P2 级口径问题，先统一术语再抽引文 |

---

## 七、审查前的 30 秒预检（避免白干）

开工前确认四件事，缺一件就先问：

1. 这是**哪一版**？文件名带版本号吗？（不同版本混审是最常见的返工原因）
2. 目标期刊与文章类型定了吗？
3. 台账在哪？如果没有，用户知道这会导致判定降级吗？
4. 这是首轮还是复审？复审的话上一轮报告在哪？

四个问题问完再动手，比审到一半发现看错了版本省得多。
