# 三路径处方库

判定结束后，按对应路径取处方。**处方必须落到"改哪一句、补哪个实验、改完看什么"**，不允许停在"建议加强"。

先读对应路径的判据（`core/rubric.md`），再回来取动作。

---

## P-A 方法创新型：证据闭环，往方法创新写

**适用**：等容量对照明显弱于本方案、统计检验齐备、缺口有负向证据。

### 逐节动作

| 位置 | 动作 | 判据 |
|---|---|---|
| 标题 | 保留方法创新词（novel / efficient / lightweight），但必须含具体机制名而非空泛"新框架" | 标题能否让读者说出"改了什么" |
| 摘要 | 五段固定序：任务背景 → 隐含假设及其缺陷 → 本文策略 → 实验设置+核心量化 → 结论价值 | 缺任一段退回 |
| 引言末段 | 三条贡献显式列出，第②条必须是方法贡献且带量化的"设计收益"而非"总收益" | 收益须是"排除容量后"的净收益 |
| 方法 | 每个模块开头加一句"针对 §1 的 X 缺陷" | 模块与缺陷一一对应 |
| 结果 | 主对比表 + 等容量对照表**分开且相邻**，让读者自己看出设计收益 | 分表是 P-A 的门面 |
| 消融 | 必须有"等参数占位"行（占位模块），这是 P-A 的命门 | 无此行 → 退回 P-B |
| 讨论 | 机理 + 文献本质区分 + 失效条件 + 回应对照质疑 | 四段缺一不可 |

### P-A 的三个高发陷阱

1. **"等容量"没做对**：只对齐了参数量，没对齐 FLOPs 或训练预算。审稿人会问"是不是训练更久"。→ 处方：在表注写明对齐了哪几维、未对齐的哪维为何不影响结论。
2. **贡献①写成了方法贡献**：科学发现贡献与方法贡献混写，导致三条贡献看起来只有一条。→ 处方：贡献①必须独立陈述"量化揭示了什么假设的什么缺陷"。
3. **对照只赢小数点**：差距虽显著但极小（<1%），此时"明显弱于"不成立。→ 处方：改走 P-B，用"可复现的小幅收益"叙事更安全。

## P-B 评估认知型：对照不足但缺口成立，往科学发现写

**适用**：对照缺失或差距微弱，但缺口有说服力、负向/失败结果扎实、数字干净。

这是**大多数真实稿件该走的路径**，也是本 skill 最有价值的处方。

### 核心转向

一句话：**从"我提出了一个更好的方法"转向"我证明了大家赖以工作的假设是错的，并给出缓解方式"。**

后者的证据门槛更低（不需要证明因果，只需要证明现象存在），而学术价值并不更低——很多高影响论文正是这一类。

### 逐节动作

| 位置 | 原（P-A 版） | 改（P-B 版） |
|---|---|---|
| 标题 | "A Novel X Framework for Y" | "Revisiting the Z Assumption in Y: Quantifying A and a Plug-in Mitigation" |
| 摘要开头 | 任务背景 + 我们提出 | 任务背景 + **业界默认 X 假设** |
| 摘要中段 | 我们的模块由 A、B 组成 | **我们量化了 X 假设在 P 协议下的偏差（给出数字）**；并给出一项可插拔缓解策略 |
| 摘要结论 | 方法显著优于基线 | 缓解策略在等预算条件下带来可复现的小幅收益；更重要的是，该结果说明只依赖原指标会高估性能 |
| 引言 | 缺口 + 方案 | 缺口 → 假设的量化验证设计 → 缓解策略作为**附属**贡献 |
| 贡献① | — | 科学发现：量化揭示 X 假设导致 Z 偏差 |
| 贡献② | 提出 XX 方法 | 给出缓解策略，其收益来自设计而非容量（附等预算对比；若无，则**不许写"来自设计"**，改写为"在等预算下可复现"） |
| 贡献③ | — | 评估认知：在 W 场景下指标 M1 比 M2 更贴合业务价值 |
| 方法节标题 | "Proposed Method" | "Diagnosis and Mitigation" |
| 实验节 | 主对比 + 对照 | **假设验证实验（核心）** + 缓解验证实验 + 负向对照（保留） |
| 讨论 | 我们更好 | 该偏差的成因 + 在哪些条件下偏差最大 + 本文结论的适用边界 |

### P-B 必须保留的三样东西

1. **负向对照**——它是"缺口真实存在"的证明，删了就退回 P-C。
2. **缓解策略的等预算对比**——哪怕差距小，也要给；这决定贡献②的措辞强度。
3. **指标对比实验**——M1 vs M2 哪个更能反映业务价值，没有这一条，贡献③是空话。

### P-B 的高发错误

- **降级不彻底**：标题改了，摘要结论句还写"outperform"。→ 审稿人一眼看出是硬撑，比不降级更糟。
- **贡献②仍写"提出"**：改判 P-B 后，贡献②的动词应降为 "provide / introduce a lightweight mitigation"，而不是 "propose a novel architecture"。
- **把评估论文写出工程味**：P-B 的价值在"证明现象"，不在"刷指标"，实验设计要围绕"偏差何时最大/最小"而不是"我们最强"。

## P-C 证据不足：先补或先撤，不许投

**适用**：命中任一 F1–F6。

### 两条出路（必须二选一，不能模糊）

**出路一：补证据（如果时间与算力允许）**

按"能翻转判定"的最小实验集排序，通常只需要 1–2 项：

| 缺失项 | 最小补做 | 补完翻转什么 |
|---|---|---|
| F1 无等容量对照 | 一个"等参数/等 FLOPs 占位模块"对照组，同预算训练 | 若弱于本方案 → 可改判 P-A；若接近 → 永久 P-B |
| F3 无对照却称因果 | 同上（F1 的补做同时解 F3），并撤掉未支撑的因果动词 | 撤销后 F3 消失，路径可能升 P-B |
| F5 隐去负向结果 | 把已做过的失败组/退化区间补回结果或 SI，并给解释 | 缺口证据增强，支撑 A 维得分 |
| F2 数字不可溯源 | 复算脚本 + 台账对齐，逐条给出处 | 解 F2 后通常直接升 P-B |
| F4 全称声明 | **不需要实验**：删掉"通用/普适"，限定适用域 | 零成本解 F4 |
| F6 完整性问题 | 提供原始数据/原图 | 无法自证则不可投 |

**出路二：撤声称（如果时间不足）**

按此顺序撤，撤到哪一步路径升到哪一档：

1. 删全称声明（"all scenarios"→"the three evaluated subsets"）
2. 解除因果表述（"due to"→"is consistent with"；"demonstrates"→"indicates"）
3. 把"提出新方法"降级为"提供缓解策略"
4. 把贡献②的证据支撑从"因果"改为"等预算下可复现"

**撤完第 1–2 步**，F3/F4 消失，路径通常可升到 P-B。
**撤完第 3–4 步**，整篇改判为评估认知型，可投。

### P-C 的红线表述

报告里必须原样写出这句（不许软化）：

> 在当前证据条件下，本稿若按现稿投递，预判结果为**拒稿**，主因是 <F 编号 + 一句话>。这不是行文问题，补润色无效。

---

## 附：路径判定的"不变量"

无论走哪条路径，以下三件事永远不做（这是学术底线，不是策略选择）：

1. **不编造实验、不虚构对照、不美化失败。**
2. **不把"未验证"写成"已验证"，不把"相关"写成"因果"。**
3. **不在缺证据时用文字包装替代证据。** 故事好看的前提，是因果对照闭环；闭环不了，就诚实降级——降级后的稿子是能过的稿子，硬撑的稿子是必拒的稿子。
