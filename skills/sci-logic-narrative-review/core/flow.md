# 执行流程：七步

每次审查严格按序执行。**每一步都有强制产出**，产出没写进报告就算这步没做。

---

## 第一步：输入盘点与缺口判定

目标是确认"我有没有资格做全量审查"。

> 需要更细的取料规则（该收哪些文件、`.docx`/`.tex`/PDF 各自的坑、抽取引文与检索声称句的具体检索式、数字核验的四组固定抽样、多轮差分追踪表）时，读 `references/input-intake.md`。本步只给必需动作，细节在那份文件里。

### 1.1 收料

| 材料 | 必需度 | 缺失后果 |
|---|---|---|
| 稿件正文（摘要/引言/结果/讨论/结论全） | **必需** | 无法审查，只出"信息不足清单" |
| 表格与图（含图注） | **必需** | L5 无法审，L3 只能部分审 |
| 实验台账 / 消融结果 / 统计输出 | **必需**（可为零散文件） | 无法双轨比对 → 触发 P0 |
| 补充材料 | 高 | 负向对照常在 SI 里，缺了容易误判 |
| 复算脚本 / 原始日志 | 中 | 数字可溯源度降级 |
| 目标期刊与文章类型 | 高 | 判定失去参照系，须先问一次 |
| 上一轮报告（非首轮时） | **非首轮必需** | 无法做差分，本轮退化为首轮审查 |

**取料原则**：宁可多问一次目标期刊，也不要猜。期刊决定"亏多少算缺陷、显著到什么程度算够"。

### 1.2 缺口分级

- **G0 完整**：稿件 + 图表 + 台账 + 期刊 → 全量审查（走第二至第七步）
- **G1 部分**：缺台账或缺 SI → 仍做全量审查，但所有涉及数字的结论标"未验证"，且**不得给 P-A 路径**
- **G2 严重**：只有摘要/提纲，或完全没有实验记录 → 不出评价性结论，出"信息不足清单 + 可审部分"（可直接套用模板的"部分审查"模式）

**判定写在报告头部的 `输入完整度` 字段，不许含糊。** 这是后面所有结论的可信度前提。

### 1.3 建立定位索引

在动手前先给稿件分节编号（如 `§1 引言`、`§4.2 消融`、`Tab.3`、`Fig.2b`、`Supp.S4`）。后面每张漏洞卡片都用这套编号定位，**不建立索引就开始写漏洞，定位一定写不出来。**

## 第二步：L1–L2 故事链前置审查（缺口与方案）

先审故事链的前两段，因为如果缺口不成立，后面所有实验都是无的放矢——此时不必浪费精力逐表核对。

- 按 `core/gap-checklist.md` 的 L1、L2 逐条过。
- 输出：缺口是否成立、缺口是否具体、方案是否逐条对症。
- **短路规则**：若 L1 判定"缺口空洞/不成立"，先看 L4（贡献是否同质化）和 L6（边界是否自限）能否救——若都不能，直接进第六步判定 P-C，**不必再花时间做 L3 的逐表核算**，在报告里说明"因缺口不成立，L3 仅做抽检"。

这不省事，这是省在正确的顺序上。

---

## 第三步：L3 因果闭环审查（最耗时的一步）

按三层实验逐层核对，**顺序不能反**：

1. **主对比层**：基线是否最新、是否同协议、是否多随机种子、是否给了 p 值/置信区间/均值±标准差。缺任一 → P1。
2. **等容量控制层**（定海神针）：是否存在与方案在参数量/通道数/计算量对齐的对照组；控制变量是否唯一；提升是否仍成立。**缺失 → P0 或 P1（视声称强度）**。
3. **泛化鲁棒层**：跨子集/跨场景/不同参数条件是否复现；负向对照与失败组是否保留并解释。

三层各自的失败模式与判据在 `core/gap-checklist.md` 的 L3。此处只强调一条：**"参数量同时增加"是本领域最高频的替代解释，没有等容量对照，任何性能提升声明都不可采信。**

---

## 第四步：L4–L6 结构性审查（贡献/图表/边界）

按清单过 L4、L5、L6。三处特别容易漏：

- **贡献三处摆放是否一致**：摘要末尾、引言末段、结论——把三段文字并排看，找出不一致（数量、措辞强度、支撑实验指向）。不一致 → P1。
- **图能否 30 秒读懂机制**：机制图若只是方块串联、没有标注"每个分支解决哪个缺陷"，判 P2。
- **Discussion 是否复述结果**：如果讨论段落的主语/谓语与结果段高度重合而缺少"为什么"，判 P1。

---

## 第五步：双轨比对（不可跳过）

拿稿件（轨 A）和台账（轨 B）逐项对照，三类：

| 比对 | 做法 | 命中判级 |
|---|---|---|
| 数字轨 | 正文每个数值 → 台账找同口径来源；随机抽 8–12 个关键数字做全量核验（含摘要里的） | 找不到或口径不同 → P1；与台账矛盾 → P0 |
| 声称轨 | 抽取全部因果/显著/最优类动词，逐个问"证据强度够吗" | 强度越级 → P1；"显著"无检验 → P1 |
| 口径轨 | 指标名、模型名、数据集划分、种子策略在全稿一致性 | 不一致 → P2；同指标两个值 → P0 |

**抽样纪律**：不能只抽好看的。抽法固定——摘要全部数字 + 主表每列首尾 + 消融表差值最大的两个 + 任意一个负向/退化结果。

**产出**：一张"数字核验表"进报告附录，逐行写"稿件值 / 台账值 / 口径 / 结论（一致/不一致/未找到）"。

---

## 第六步：评分与路径判定

按 `core/rubric.md` 打分，然后**先查硬阈值再查总分**（总分只用于排序，不用于判定）。

判定必须回答三个问题：

1. 走哪条路径（P-A / P-B / P-C）？
2. **为什么不能走另外两条？** （这条不写，判定就是拍脑袋）
3. 要让路径升级一档，**最小需要补什么**？

---

## 第七步：生成报告并自检

1. 用 `assets/report-template.md` 骨架填。
2. 落盘到 `<稿件目录>/审稿报告_SCI逻辑叙事审查_<YYYYMMDD>_<轮次>.md`。
3. 跑自检：

```powershell
python "<SKILL_DIR>/scripts/check_report.py" "<报告路径>"
```

4. 自检不过就补，**不许交一份自检不通过的报告**。
5. 若本轮不是首轮，在报告里加"上轮漏洞闭环差分表"（逐条：已修复/未修复/部分修复/申诉成立）。

## 每步的产出对照表（自查用）

| 步骤 | 若无以下产出，即未完成 |
|---|---|
| 一 | 输入完整度等级 + 定位索引 |
| 二 | L1、L2 结论各一句 + 支撑引文 |
| 三 | 三层实验的齐备性判断 + 每层缺失项 |
| 四 | 三条贡献并排比对结果 + 图表分层判断 + 边界陈述判断 |
| 五 | 数字核验表（≥8 行） + 声称强度越级清单 |
| 六 | 路径判定 + 排除另两条的理由 + 最小升级实验集 |
| 七 | 报告文件 + 自检通过 |
