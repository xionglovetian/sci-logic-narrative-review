# 报告契约

报告不是摘要，是**可执行的判决书**。以下为硬性契约，缺任一项即报告不合格。

## 一、必须存在的八个部分

| # | 部分 | 缺了会怎样 |
|---|---|---|
| 1 | **元信息头** | 无法追溯是哪一稿、哪一轮、什么输入 |
| 2 | **判决摘要**（5 行内可读完） | 用户拿不到结论，等于没审 |
| 3 | **评分表** | 判定不可复核 |
| 4 | **漏洞卡片**（至少 1 张 P1 或 P2） | 违反"零漏洞不可能"原则 |
| 5 | **数字核验表**（≥8 行） | 双轨比对没做 |
| 6 | **正面资产清单** | 作者不知道哪些不能动、容易被改坏 |
| 7 | **下一步顺序**（按投入产出排序） | 报告不可执行 |
| 8 | **本轮边界声明** | 覆盖范围不明，后续轮次会误信 |

## 二、元信息头字段（全部必填）

```
审查对象    ：<文件名 / 版本号>
审查轮次    ：r<N>
审查日期    ：YYYY-MM-DD
目标期刊    ：<期刊名> / <文章类型>
输入完整度  ：G0 完整 | G1 部分 | G2 严重
审查范围    ：全文 | 局部（<节名>）| 部分审查（<未覆盖项>）
路径判定    ：P-A 方法创新型 | P-B 评估认知型 | P-C 证据不足
预估结果    ：大修 / 中修 / 小修 / 必拒 / 无法判定
```

`预估结果` 必须与 `路径判定` 自洽：P-C 不能配"小修"。

## 三、漏洞卡片的固定字段（八项，缺一项不合格）

```markdown
### [编号] <一句话说清问题>
- **类别**：L1 缺口 | L2 对症 | L3 因果 | L4 贡献 | L5 图表 | L6 边界 | D 数字/声称
- **严重度**：P0 / P1 / P2 / P3
- **定位**：<章节编号> «原文引文，≤30 字，可加省略号»
- **证据**：<台账文件/表号/图号/统计输出；或"稿件内自相矛盾处">
- **审稿人原话**：「<以审稿人口吻写的、可直接进意见书的一句话>」
- **为什么有问题**：<2–3 句，说明推理链断在哪一环>
- **修改处方**：<具体动作：改写/补实验/降级声称/并表/删句；要能直接执行>
- **复审判据**：<下一轮看到什么就认为已修复>
```

**编号规则**：`V-<两位序号>`，如 `V-01`。跨轮沿用同一编号，方便差分。

**定位强制**：`定位` 字段填不出"章节 + 引文"的，说明这条是主观印象，删掉，不要写进报告。这是本契约最重要的一条——**报告里每一条都必须指得回稿件上的具体位置。**

## 四、数字核验表格式

| # | 位置 | 稿件值 | 台账值 | 口径（数据集/划分/种子/协议） | 结论 |
|---|---|---|---|---|---|
| 1 | 摘要 | 92.3% | 92.31% | A 集 test / 3 seed 均值 | 一致（四舍五入） |
| 2 | Tab.3 行2 | +4.1 mAP | 2.7 mAP | 不同划分 | **不一致 → P0** |

结论只用四种值：`一致`、`一致（需注明口径）`、`不一致`、`未找到来源`。后两种必须同时对应一张漏洞卡片。

## 五、正面资产清单（容易被忽略但必须有）

列出本稿**不应该被改动**的东西：已闭环的控制实验、写得好的缺口陈述、已量化的贡献句、清晰的机制图。

作用有两个：一是防止作者在混乱中把好东西改坏；二是让报告的"诊断"显得可信——**一个只会挑刺的审稿人不可信，一个能指出哪块承重的审稿人才可信。**

## 六、下一步顺序的排序规则

按 **投入产出比** 排序，不按严重度排序：

1. 先做**能翻转路径判定**的事（哪怕成本高）——比如补等容量对照
2. 再做**不改实验就能做**的降级与改写（成本近零，直接降低被拒概率）
3. 再做**纯加分**的措辞与图表整理

每项写清：动作、预计成本（半天/几天/需补实验）、对判定影响（翻转路径 / 降一级风险 / 不影响判定）。

## 七、本轮边界声明（防误用）

固定写三句：

1. 本轮**覆盖**了什么（镜头 + 章节 + 抽验的数字条数）
2. 本轮**未覆盖**什么（缺的输入、跳过的镜头、未核验的数字）
3. 本报告的结论**不适用于**什么（比如"仅适用于当前版本，稿件改动超过 §4 后需重审"）

## 八、结论性用语的红线

| 禁止写 | 改写成 |
|---|---|
| "整体质量不错，建议润色" | 具体到哪一句怎么改，否则不写 |
| "数据看起来没问题" | 未核验就说未核验，核验过就列核验表 |
| "建议补充更多实验" | 指明哪个实验、补完翻转哪一项判定 |
| "创新性略显不足" | 指明哪条贡献与哪条同质、缺哪类支撑实验 |
| "想必作者也意识到了" | 删掉，这不是审查语言 |
| "基本符合发表要求" | 给路径判定与预估结果，不给模糊赞誉 |

## 九、落盘与命名

```
<稿件目录>/审稿报告_SCI逻辑叙事审查_<YYYYMMDD>_r<N>.md
```

- 多轮并存，**永不覆盖**
- 新轮次报告开头必须附「上轮漏洞闭环差分表」：

| 上轮编号 | 状态 | 本稿证据 |
|---|---|---|
| V-01 | 已修复 | §4.2 新增等容量对照 Tab.4 |
| V-02 | 未修复 | 摘要仍写 significantly，无检验 |

状态只用四种：`已修复`、`部分修复`、`未修复`、`申诉成立`。**"部分修复"必须写明还缺什么。**
