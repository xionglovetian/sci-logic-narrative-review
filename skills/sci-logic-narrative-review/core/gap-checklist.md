# 七类漏洞检查清单

用法：逐条过。**每条"是"就要落到一张漏洞卡片上**（D 类额外进数字核验表）。
标 ⚑ 的是**致命项**：命中即 P0，且直接约束路径判定。

---

## 一、缺口真实性（L1）

审的是：引言指出的科学缺口，是真缺口还是套话。

| # | 检查项 | 命中判级 |
|---|---|---|
| 1.1 ⚑ | 开篇第一段是否直接介绍数据集/模型/自己改了什么，而没有先指出领域缺口 | P1 |
| 1.2 ⚑ | 缺口表述是否属于空话："现有方法精度不足""难以满足需求""仍有提升空间"——没有具体到机制或评估协议 | P1 |
| 1.3 | 缺口是否指向一个**领域内默认成立但未被系统量化/质疑**的隐含假设（而不是"没人做过"） | 未指向假设 → P1 |
| 1.4 | 是否说明了该假设失效后会带来什么**具体偏差/评估失真**（可量化的后果） | 未说明 → P1 |
| 1.5 | 缺口是否紧贴本文任务场景（换一个任务也成立的缺口 = 太泛） | 太泛 → P2 |
| 1.6 ⚑ | 缺口是否有证据支撑（负向对照、失败组、文献量化数据），而不只是作者断言 | 纯断言 → P1（若同时无负向结果，升 P0） |
| 1.7 | 缺口与后文实验是否一一对应（后文是否真的去验证了这个缺口） | 不对应 → P1 |

**L1 的核心判据**：把缺口那句话单独拿出来，问"如果这句话是真的，领域里会有人吃亏，作者能指出是谁在哪个环节吃亏吗？"答不出来 = 空话。

---

## 二、方案对症性（L2）

审的是：每个模块是不是为了补 L1 的某个缺陷而存在。

| # | 检查项 | 命中判级 |
|---|---|---|
| 2.1 | 是否每个模块/策略都写明它对应 L1 的哪一条缺陷 | 有模块无对应 → P1 |
| 2.2 | 模块的设计动机是否写成"为了提升性能/精度"（这是结果，不是动机） | P1 |
| 2.3 ⚑ | 模块的功能描述是否与实验结果脱节（说了防 X，实验里没有关于 X 的验证） | P1 |
| 2.4 | 是否说明了方案的工程属性（轻量/即插即用/不改骨干/可迁移），且该属性有代价说明 | 只吹优点 → P2 |
| 2.5 | 方案复杂度是否与缺口大小匹配（小缺口配巨型架构 = 过度设计，审稿人会问必要性） | P2 |
| 2.6 | 多模块之间是否有互补逻辑说明（为什么需要 A *和* B，单独 A 行不行） | 缺 → P1（并与 L3 消融联动） |

---

## 三、因果闭环（L3）—— 权重最高

分三层审。**第一层不齐不要进第二层**（否则得出的"缺对照"结论会失焦）。

### 3.1 第一层：主对比

| # | 检查项 | 命中判级 |
|---|---|---|
| 3.1.1 ⚑ | 基线是否为近年主流且同协议复现（不是拿三年前的弱基线） | P1 |
| 3.1.2 ⚑ | 是否有统计检验（p 值 / 置信区间 / 均值±标准差 / 多随机种子） | 全无 → P1 |
| 3.1.3 | 提升幅度是否明确区分"绝对值提升"与"相对值提升" | 混用 → P2 |
| 3.1.4 | 是否报告了方差/波动范围，使读者能判断提升是否在噪声内 | 缺 → P1（若同时无检验 → P0） |
| 3.1.5 | 对比表是否口径一致（同数据集、同划分、同评价协议、同输入分辨率/尺寸） | 不一致 → P0 |

### 3.2 第二层：等容量控制对照（定海神针）

| # | 检查项 | 命中判级 |
|---|---|---|
| 3.2.1 ⚑ | 是否存在与方案在**参数量 / 通道数 / 计算量**上对齐的对照组 | 无 → **P0** |
| 3.2.2 ⚑ | 若提升伴随参数量/计算量增加，是否明确排除了"容量红利"这一替代解释 | 未排除却宣称设计贡献 → **P0** |
| 3.2.3 | 控制变量是否唯一（同时改了两处以上 = 对照失效） | P1 |
| 3.2.4 | 对照组是否用了与方案等量的训练预算（epoch/增广/调参力度） | 未说明 → P1 |
| 3.2.5 | 单模块消融是否齐备（整模型 −A、−A 加等量参数占位） | 缺"等参数占位" → P1 |
| 3.2.6 | 是否报告了对照组"打平"或"反超"的情况（有则更可信，无则要问是否只报有利结果） | 疑似选择性报告 → P1 |

**3.2 的唯一判据**：把方案换成"同样多的参数随便堆一个"，性能会不会一样？回答不了这个问题，因果就没闭环。

### 3.3 第三层：泛化与鲁棒

| # | 检查项 | 命中判级 |
|---|---|---|
| 3.3.1 | 是否跨子集/跨场景/跨数据集验证 | 全无 → P1（若声称通用 → P0） |
| 3.3.2 | 是否覆盖不同参数条件 / 超参敏感性 | 无 → P2 |
| 3.3.3 ⚑ | 负向对照、失败实验组是否保留并解释 | 被删除或一笔带过 → P1 |
| 3.3.4 | 是否给出性能退化区间或失效条件（不只是"表现仍然良好"） | 缺 → P1 |
| 3.3.5 | 多随机种子复现是否给出种子数与结果分布 | 只说"3 次"无分布 → P2 |

---

## 四、贡献可分性（L4）

| # | 检查项 | 命中判级 |
|---|---|---|
| 4.1 ⚑ | 是否在**三处**（摘要末尾、引言末段、结论）显式摆出贡献 | 缺任一处 → P1 |
| 4.2 ⚑ | 三条贡献是否互相独立（不是同一个意思换词） | 同质 → **P1**（严重同质且无其他贡献 → P0） |
| 4.3 | 每条贡献是否标注了专属支撑实验（哪张表/哪个图） | 无支撑 → P1 |
| 4.4 | 是否做了贡献分类（科学发现 / 方法策略 / 评估认知），而非三条全写"提出一个新网络" | 全同类 → P1 |
| 4.5 | 贡献表述是否量化（带核心数字或明确对比），而非"显著提升" | 模糊 → P2 |
| 4.6 | 三处表述是否一致（数量、强度、指向的实验） | 不一致 → P1 |
| 4.7 | 是否有贡献超出证据边界（贡献句的强度 > 实验能支撑的强度） | 越界 → P1（因果类越界 → P0） |

**L4 快速检测法**：把三条贡献写成三行，遮住专有名词，只留动词和对象。如果三行看起来是同一句话 → 同质化成立。

---

## 五、图表分层（L5）

| # | 检查项 | 命中判级 |
|---|---|---|
| 5.1 | 是否有机制示意图，且标注每个分支/模块的功能与设计动机 | 无机制图 → P1 |
| 5.2 | 机制图能否在 30 秒内看出与基线的差别与互补逻辑 | 只是方块堆叠 → P2 |
| 5.3 ⚑ | 是否把主对比/消融/鲁棒混在一张表里 | 混装 → P2，若因此掩盖了对照缺失 → 升 P1 |
| 5.4 | 表格是否按逻辑分组（主结果 / 控制消融 / 鲁棒统计 / 补充材料） | 未分组 → P2 |
| 5.5 | 是否标注显著性标记、p 值、置信区间 | 缺 → P1（与 3.1.2 联动，不重复计分） |
| 5.6 | 是否有趋势可视化（指标随关键变量变化的折线/散点），把文字结论可视化 | 全无 → P2 |
| 5.7 | 图注是否自足（不读正文也能懂）、是否标了口径 | 不自足 → P2 |
| 5.8 | 图中是否有未解释的异常点/离群点被回避 | 回避 → P2 |
| 5.9 | 图与表是否重复表达同一信息（浪费篇幅） | P3 |

---

## 六、边界自限（L6）

| # | 检查项 | 命中判级 |
|---|---|---|
| 6.1 ⚑ | Discussion 是否整体在复述 Results（主语谓语高度重合、没有"为什么"） | P1 |
| 6.2 | 是否解释了内在机理（组件如何起作用、为何互补） | 缺 → P1 |
| 6.3 | 是否与已有文献做了**本质**区分（不是"我们效果更好"） | 只比性能 → P1 |
| 6.4 | 是否主动回应了控制对照实验可能引出的质疑 | 缺 → P1 |
| 6.5 ⚑ | 是否明确写明失效条件 / 效果变差的场景 / 验证的数据范围 | 缺 → P1 |
| 6.6 | 是否存在"通用/普适/any scenario"类无证据支撑的全称声明 | P0 |
| 6.7 | 未来工作是否具体（指向可执行的下一步），而非"进一步研究" | 空泛 → P3 |
| 6.8 | Results 是否越界做机理解释（应放 Discussion） | 越界 → P2 |

**L6 的核心判据**：Discussion 里能不能找到一句"我们的方法在 ___ 情况下会失效"？找不到 → P1，因为审稿人会替作者写这句话，而且写在拒稿理由里。

---

## 七、数字与声称（D）—— 双轨比对的落点

| # | 检查项 | 命中判级 |
|---|---|---|
| 7.1 ⚑ | 正文数值能否在台账中找到同口径来源 | 找不到 → P1；矛盾 → **P0** |
| 7.2 ⚑ | "显著/significantly"是否都有统计检验支撑 | 无 → P1 |
| 7.3 ⚑ | 因果动词（prove / demonstrate / attribute to / due to）是否都有等容量对照支撑 | 无 → **P0** |
| 7.4 | "state-of-the-art / 最优"是否在最新且同协议的对比下成立 | 不成立 → P1 |
| 7.5 | 同一指标是否在摘要/正文/表/图注中口径一致 | 两值并存 → **P0** |
| 7.6 | 四舍五入是否统一、单位是否统一 | P2 |
| 7.7 | 相对提升的计算基数是否写清（避免"提升 20%"歧义） | P2 |
| 7.8 | 引用的对比方法数字是否来自原文而非本文复现（需标明来源） | 未标 → P2 |
| 7.9 | 是否存在"孤儿数字"（正文出现但无表无图无台账） | P1 |

## 附录：六类致命项速查（命中即 P0，且路径不能给 P-A）

| 致命项 | 定位方式 |
|---|---|
| F1 核心提升可能来自容量增加，无等容量对照 | 查 3.2.1 / 3.2.2 |
| F2 数字不可溯源或与台账矛盾 | 查 7.1 / 7.5 |
| F3 无对照却宣称因果 | 查 7.3 |
| F4 全称声明（通用/普适）无跨域证据 | 查 6.6 |
| F5 负向/失败结果被系统性隐去 | 查 3.3.3 |
| F6 疑似图像/数据完整性问题（图重复、拼接、数值异常整齐） | 逐图比对 |

**F 类问题一旦命中，报告首屏必须单独列出，不允许只埋在卡片列表里。**
