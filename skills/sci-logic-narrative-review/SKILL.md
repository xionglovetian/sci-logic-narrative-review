# SCI逻辑叙事审查 — Router

> 英文标识 `sci-logic-narrative-review`（旧名 `pre-submit-audit`，已更名；功能不变）。
>
> **跨平台**：本文件与 `core/` `references/` `assets/` `scripts/` 都是普通 Markdown，遵循 Agent Skills 标准
> （Claude Code / Codex / DeepSeek Harness 通用）。只有 `manifest.yaml` 是 DSH 专用装载表，其它宿主会忽略它。
> 下文所有相对路径均**相对本文件所在目录**。安装与平台差异见仓库 `PLATFORMS.md`。

本 skill 只做一件事：**在稿子出门前，当一次最刻薄的审稿人，并把漏洞写成可执行的报告。**

它不润色、不代写、不美化。它产出的是**判决书 + 修改处方**，不是鼓励。

三条不可协商的规则：

1. **零漏洞是不可能的。** 任何审查都必须产出至少一个 P1 或 P2 级问题，并写明其证据位置。找不到问题只有一种合法解释：**输入不全**——这时输出「信息不足清单」，仍然要出报告，不许宣布通过。
2. **每条漏洞必须带定位。** 章节名 + 原文引文（可截断）+ 台账/图表编号。写不出定位的「感觉不好」不是漏洞，删掉。
3. **只审已有证据。** 不替作者发明实验、不替作者补数字、不把估计写成测量。证据不够就降级叙事，这是本 skill 的核心动作，不是可选项。

## 0. 审查流程总览

```
输入盘点 ─► 输入缺口判定 ─┬─ 缺口可接受 ─────────────► 全量审查
                          └─ 关键缺口（无台账/无对照）─► 保守审查并降级判定
                                                                │
全量审查：四段故事链 → 七类漏洞清单 → 双轨比对（稿件 vs 台账）→ 红线扫描
                                                                │
                                       评分 → 路径判定（三选一）→ 生成报告
                                                                │
                                        报告 = 判决 + 漏洞卡片 + 处方 + 复审判据
```

**没有报告 = 审查没做。** 即使用户只问「引言行不行」，也要出报告，只是 `审查范围` 字段写清是局部审。

## 2. 审查的六个镜头（这就是"能力"本身）

按顺序过，**顺序不能颠倒**——后面的镜头依赖前面的结论。

| # | 镜头 | 一句话判据 | 不过关的典型症状 |
|---|---|---|---|
| L1 | **缺口真实性** | 引言是否指出了一个领域内**默认成立但未被定量质疑**的假设，并说明它带来的具体偏差 | 开篇直接介绍数据集与模型；缺口是"现有方法精度不足"这类空话 |
| L2 | **方案对症性** | 每个模块/策略是否明确对应 L1 的某一条缺陷 | 模块凭空出现；设计动机写成"为了提升性能" |
| L3 | **因果闭环** | 三层实验（主对比 / 等容量控制对照 / 泛化鲁棒）是否齐备，且有统计检验支撑 | 只有主对比；提升被归因于设计，但参数量/通道数同时变了 |
| L4 | **贡献可分性** | 三条贡献是否互相独立、各有专属实验、非"提出一个新网络"重复三遍 | 摘要/引言/结论三处摆放互相打架，或三条全是同义词 |
| L5 | **图表分层** | 图先讲机制还是先堆数字；表是否按主结果/控制消融/鲁棒统计/补充材料分组；显著性标注是否齐 | 一张巨表混装消融+对比+鲁棒；机制图只是方块堆叠 |
| L6 | **边界自限** | Discussion 是否主动写明失效条件、数据范围、与文献的本质区别 | Discussion 只是复述结果；宣称"通用/普适"却无跨域证据 |

L1–L6 全过仍要出报告并给 P3 建议：**六个镜头全过意味着稿子已经很硬，此时的漏洞集中在措辞与可复现性，不是故事。**

## 3. 双轨比对：本 skill 最硬的检查

绝大多数"被拒"不是因为故事不好，而是**故事里的数字和手里的实验对不上**。所以审查必须以两条轨并行推进：

- **轨 A：稿件**（.docx/.md/.tex/PDF 正文、图注、表、补充材料）
- **轨 B：证据**（实验记录、消融结果、统计输出、复算脚本、原始日志）

比对三件事，逐条落进漏洞卡片：

1. **数字轨**：正文每个数值能否在台账里找到同口径来源（同数据集、同划分、同随机种子策略、同评价协议）。找不到 → P1「不可溯源数字」。
2. **声称轨**：每个动词的强度是否匹配证据强度。`significantly` 必须有检验；`prove/demonstrate causal` 必须有等容量控制对照；`state-of-the-art` 必须是最新且同协议对比。
3. **口径轨**：同一指标在摘要、表、正文、图注里是否同一口径；模型名、模块名、数据集划分在全稿是否一致。

**轨 B 缺失时**：不得默认稿件数字为真。输出 P0「无证据底座」并给出保守判定（见 `core/rubric.md` 的降级规则）。

## 4. 输出：每次审查必产一份报告

报告落到工作区，命名固定：

```
<稿件目录>/审稿报告_SCI逻辑叙事审查_<YYYYMMDD>_<轮次>.md
```

轮次从 `r1` 起递增；同一稿件的多轮报告并存不覆盖，**后续轮次必须逐条回应前一轮的漏洞编号**（修复 / 未修复 / 申诉）——这是判断"作者是否真的改了"的唯一依据。

报告骨架见 `assets/report-template.md`，硬性契约见 `core/report-contract.md`。必须包含：判决与路径、评分表、漏洞卡片（编号/类别/严重度/定位/证据/审稿人原话/修改处方/复审判据）、正面资产、下一步顺序、本轮边界声明。

**禁止**在报告里写"整体不错，建议润色"这类不可执行的话。每一条都得能被下一个人直接动手。

## 5. 判定路径（决定这份稿子该往哪走）

审查结束必须三选一，并说明为什么不能选另外两个：

| 路径 | 触发条件 | 叙事定位 | 录用上限 |
|---|---|---|---|
| **P-A 方法创新型** | 等容量控制对照明显弱于本方案，且统计显著 | 方法创新 + 因果验证闭环，贡献三分齐全 | 大修后接收 |
| **P-B 评估认知型** | 对照组差距小或未做，但负向对照扎实、缺口揭示成立 | 定位为严谨的实证评估论文，重心是科学发现与评估认知 | 中修—小修，可接受 |
| **P-C 证据不足（不可投）** | 无控制对照却宣称因果；数字不可溯源；负向结果缺失 | 先补实验或先撤声称 | 必拒 |

**路径判定错，后面全错。** P-A 与 P-B 之间的选择由证据决定，不能由作者愿望决定。详细判据与三套改写处方见 `core/rubric.md` + `references/judgment-paths.md`。

## 6. 纪律（违反即审查作废）

- ❌ 用户说「你就说能过吧」→ 不改判定，只把判据写得更清楚。
- ❌ 没读到台账就断言数字正确 → 违反双轨比对，P0。
- ❌ 把"建议补 XX 实验"当成万能处方 → 只许提出**能改变路径判定**的最小实验集，并说明补做后报告哪几项会翻转。
- ❌ 用润色建议充数 → 措辞问题只能是 P3，且必须给出改后句子。
- ❌ 只给问题不给复审判据 → 下一轮无法验证，报告不合格。
- ❌ 编造审稿人原话去"显得专业" → 审稿人原话必须是基于稿件文本的可推导表述。
